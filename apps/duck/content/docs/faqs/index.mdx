## General

### What is gentleduck?

A set of React packages that ship under the `@gentleduck` npm scope. The headline pieces are headless primitives, Tailwind-styled components, a calendar engine, a CLI, and a keyboard command engine. Each package is independently versioned and independently useful.

### Is this another shadcn/ui clone?

No. The copy-paste philosophy is the same — you own the component source — but the layer underneath is different. shadcn/ui ships components built on Radix primitives. gentleduck ships its own primitives that are 50–92% smaller per component because shared internals load once. The CLI also goes further: it can `update`, `diff`, `remove`, and `list` components, not only `add`.

### Is it production-ready?

The primitives, components, calendar, CLI, vim, variants, motion, hooks, libs, lazy, state, registry-build, and iam packages are published on npm and used in production. The version numbers reflect maturity per package — see each package page for status.

## Primitives

### How is it smaller than Radix?

Radix publishes one npm package per primitive. Each one ships its own copy of focus management, dismissal logic, presence animation, and ARIA helpers. With many primitives in one app you pay for the same internals many times. `@gentleduck/primitives` is a single package — the shared internals load once. Bundle reports for individual primitives drop 50–92% in real apps.

### Do I have to migrate everything at once?

No. The compound-component API (`Dialog.Root`, `Dialog.Trigger`, `asChild`, `data-state` attributes) matches Radix on purpose. Most migrations are a namespace swap in your imports. You can run both side by side while you move components piece by piece.

### Is it accessible?

Yes. Every primitive ships with ARIA roles, keyboard navigation, focus management, and screen reader announcements equivalent to Radix. Tests live alongside each primitive in `packages/duck-primitives/src`.

## Components

### Where do styled components live?

In `@gentleduck/registry-ui`. They're not installed via npm — the CLI copies the source into your app so you own and can edit every line. Tailwind 4 + CSS variables drive the theming.

### Can I use them without the CLI?

Yes — clone or reference the source in `packages/registry-ui` and copy what you need. The CLI exists to keep imports, dependencies, and updates consistent over time.

### Do they work with my design system?

The Tailwind tokens map onto CSS variables. Override the variables and you have your design system. If you want fully custom styles, drop down a layer to `@gentleduck/primitives` and bring your own CSS.

## Calendar

### Why a separate calendar package?

Because most React calendars hard-code the Gregorian system, ship every locale, and weigh 20+ KB. `@gentleduck/calendar` is 5 KB, headless, and supports seven date systems through pluggable adapters: Gregorian, Islamic, Persian, Hebrew, Buddhist, Indian, and Japanese.

### Does it replace `react-day-picker`?

It can — see the [comparison](/docs/comparisons/vs-react-day-picker) for the migration path. The shape of the API is different (it's headless, you bring the rendering), but you gain the multi-calendar support and you drop the `date-fns` dependency.

## CLI

### How does `update` work?

`@gentleduck/cli update` pulls the latest registry source for components you've already added, three-way merges with your local edits, and shows a diff before writing. `diff` shows the same comparison without writing. `remove` reverses `add` cleanly.

### Can I publish my own components through it?

Yes. `@gentleduck/registry-build` compiles a folder of components into a registry index that the CLI can `add` from. The duck-ui docs site is itself built on this.

## Project

### Is it open source?

Yes — MIT licensed. The repository is [github.com/gentleeduck/duck-ui](https://github.com/gentleeduck/duck-ui).

### How do I report a bug or request a feature?

Open an issue on the [GitHub tracker](https://github.com/gentleeduck/duck-ui/issues). For component-specific bugs, include the component name and a minimal reproduction.

### Can I sponsor the project?

Sponsorship details and the sponsor link live in the site footer. The project is maintained by a small team and any support directly extends the time available to keep packages updated.

### Where is the changelog?

Per-month entries live under [/docs/changelog](/docs/changelog). Each published package also keeps its own `CHANGELOG.md` driven by Changesets.
