## @gentleduck/calendar - Headless Calendar Engine <Badge>feat</Badge>

Published [`@gentleduck/calendar`](https://www.npmjs.com/package/@gentleduck/calendar) - a headless, zero-dependency calendar engine for React.

### What it does

One hook (`useCalendar`) gives you grid generation, selection state, keyboard navigation, ARIA announcements, and month traversal. You bring your own UI.

```tsx
import { useCalendar, NativeAdapter } from '@gentleduck/calendar'

const adapter = new NativeAdapter()

function MyCalendar() {
  const { state, getDayProps, getGridProps } = useCalendar({
    adapter,
    mode: 'single',
  })

  return (
    <div {...getGridProps()}>
      {state.weeks.map((week) => (
        <div key={week.weekNumber} role="row">
          {week.days.map((day) => (
            <button key={day.date.toISOString()} {...getDayProps(day)}>
              {day.date.getDate()}
            </button>
          ))}
        </div>
      ))}
    </div>
  )
}
```

### Date adapter pattern

All date operations go through the `DateAdapter<TDate>` interface. Swap date libraries or calendar systems without changing component code:

```tsx
// Native Date (0 dependencies)
import { NativeAdapter } from '@gentleduck/calendar'

// Or use dayjs, date-fns, Luxon
import { DayjsAdapter } from '@gentleduck/calendar/adapter'

// Or switch to non-Gregorian calendars
import { IslamicAdapter, PersianAdapter, HebrewAdapter } from '@gentleduck/calendar/adapter'
```

### 4 calendar systems

| Calendar | Adapter | Leap year support |
| --- | --- | --- |
| Gregorian | `NativeAdapter` | Standard |
| Islamic (Hijri) | `IslamicAdapter` | 30-year tabular cycle |
| Persian (Jalali) | `PersianAdapter` | 2820-year Borkowski cycle |
| Hebrew | `HebrewAdapter` | 19-year Metonic cycle (13 months) |

### Selection modes

```tsx
// Single date
useCalendar({ adapter, mode: 'single' })

// Date range with auto-swap
useCalendar({ adapter, mode: 'range' })

// Multi-select
useCalendar({ adapter, mode: 'multi' })

// Multi-range with shift+click splitting
useCalendar({ adapter, mode: 'multi-range' })
```

### Compound primitives

Built compound components in `@gentleduck/primitives/calendar`:

```tsx
<Calendar.Root adapter={adapter} mode="single">
  <Calendar.Header />
  <Calendar.Nav />
  <Calendar.Grid>
    <Calendar.Weekdays />
    {/* Calendar.Day for each day */}
  </Calendar.Grid>
  <Calendar.MonthView />
  <Calendar.YearView />
</Calendar.Root>
```

## Presence Animation Interrupt <Badge>fix</Badge>

Fixed a critical bug in `@gentleduck/primitives` where rapidly opening and closing popover/dialog/sheet would cause the content to glitch or disappear.

**Root cause:** When re-opening during an exit animation, the old animation's `animationend` event fired after the re-mount, causing `Presence` to unmount the re-opened content.

**Fix:** Cancel in-flight exit animations by resetting `animationName` on the DOM node when `present` flips back to `true`. The enter animation starts fresh with no stale events.

```tsx
// Before: rapid open/close would glitch
<Popover open={open} onOpenChange={setOpen}>
  {/* Content would flash or disappear */}
</Popover>

// After: each click interrupts and snaps to the new state
```

This fix applies to all animated primitives: Popover, Dialog, AlertDialog, Sheet, Tooltip, HoverCard, DropdownMenu, ContextMenu, Select, and NavigationMenu.

## Registry Build - Extension-Driven Architecture <Badge>feat</Badge>

Major refactoring of `@gentleduck/registry-build` into a fully extension-driven build system with generic collections support.

### Extension-driven runner

The core runner no longer has built-in index or components phases. All processing is now performed by explicit extensions that consumers register in their config:

- `bannerExtension()` - CLI banner output (beforeBuild)
- `validateExtension()` - source path and registry entry validation (beforeBuild)
- `indexBuildExtension()` - registry entry materialization and `index.json` generation (afterBuild)
- `componentsExtension()` - per-item JSON component payload generation (afterBuild)
- `componentIndexExtension()` - framework-specific import index generation (afterBuild)
- `colorsExtension()` - theme CSS and color JSON generation (afterBuild)

Use `uiRegistryPreset()` to bundle all standard UI extensions, or register them individually for full control.

### Generic collections

New `collections` config surface for non-UI consumers. Collections hold file-backed data, named source trees, and arbitrary metadata. Extensions read collections without assuming UI registry structure.

### Config composition

- File-based `extends` with path-aware resolution (source paths, data files resolve relative to the declaring config)
- Code-driven `mergeRegistryBuildConfigs()` for parameterized preset factories
- Monorepo-specific presets moved out of the package to consumer-local config files

### Codebase hardening

- Consolidated over-split config files (`types.ts`, `defaults.ts` merged back to single files)
- Removed dead code (unused logger, duplicate type aliases, unexported internal helpers)
- Added JSDoc to all exported functions across `lib/`, `pipeline/`, `extensions/`, and `config/`
- Added unit tests for config merge, defaults, change detection, and framework adapters
- 51 tests across 7 test files with 109 assertions

See the full [registry-build docs](/www/packages/duck-registry-build).
