## Quick comparison

| | gentleduck/ui | shadcn/ui |
|---|---|---|
| **CLI** | `gentleduck add`, `init`, `diff`, `update`, `remove` | `shadcn add`, `init`, `diff` |
| **Component count** | 50+ styled components | 50+ styled components |
| **Primitives** | Own (`@gentleduck/primitives`) | Radix UI (dependency) |
| **Calendar** | Own engine (`@gentleduck/calendar`, ~5 KB) | react-day-picker (~20 KB) |
| **Motion / Animation** | `@gentleduck/motion` (tokens, reduced-motion) | None (BYO) |
| **Keyboard engine** | `@gentleduck/vim` (bindings, sequences, recorder) | None (BYO) |
| **State management** | `@gentleduck/state` (atom-based) | None (BYO) |
| **Variant system** | `@gentleduck/variants` (cva) | cva (class-variance-authority) |
| **Styling** | Tailwind + `data-*` selectors | Tailwind + `cn()` |
| **Source ownership** | Full (copy-paste) | Full (copy-paste) |
| **TypeScript** | Full type safety | Full type safety |
| **Framework** | React 19 | React 19 (v2), React 18 (v1) |

## Same philosophy

Both projects share the same core principle: **you own the code**. Components are copied into your project, not installed as dependencies. You can modify anything.

### Copy-paste components

Both use a CLI to scaffold components into your codebase:

```bash
# shadcn
npx shadcn@latest add button

# gentleduck
npx gentleduck add button
```

The result is the same: a component file in your project that you own and can edit freely.

### Tailwind CSS

Both use Tailwind for styling. Both use a `cn()` utility for class merging. Both support theming through CSS variables.

### Compound component patterns

Both structure complex components (Dialog, Dropdown, Sheet) using the Root / Trigger / Content compound pattern. The JSX looks nearly identical.

## What gentleduck adds

### Own primitives

shadcn/ui depends on Radix UI for its headless primitives. When Radix changes behavior or deprecates an API, your styled components are affected.

gentleduck/ui uses `@gentleduck/primitives` -- the same compound-component API as Radix, but you own the source. The primitives live in `packages/duck-primitives/` in your monorepo. Modify focus trapping, dismiss behavior, or animation hooks directly. See the [full comparison with Radix](/docs/comparisons/vs-radix).

### Calendar engine

shadcn/ui wraps react-day-picker (~20 KB gzipped, requires date-fns).

gentleduck/ui uses `@gentleduck/calendar` (~5 KB gzipped, zero required dependencies). The adapter pattern lets you use native Date, date-fns, dayjs, or luxon. Non-Gregorian calendars (Hijri, Persian) work through adapters. See the [full comparison with react-day-picker](/docs/comparisons/vs-react-day-picker).

### Keyboard engine

`@gentleduck/vim` provides a keyboard command system: key bindings, multi-key sequences (vim-style), macro recording, and platform-aware formatting (`Cmd` on Mac, `Ctrl` elsewhere). shadcn/ui has no keyboard abstraction.

```tsx
import { useKeymap } from '@gentleduck/vim/react'

useKeymap({
  'Mod+k': () => openCommandPalette(),
  'Mod+s': () => save(),
  'g g': () => scrollToTop(),
})
```

### Animation tokens

`@gentleduck/motion` provides prebuilt animation keyframes and a reduced-motion system that integrates with the Presence primitive. shadcn/ui leaves animation entirely to the user.

### State management

`@gentleduck/state` provides an atom-based state management system. shadcn/ui does not include state management tooling.

### Extended CLI

| Command | gentleduck | shadcn |
|---|---|---|
| `init` | Yes | Yes |
| `add` | Yes | Yes |
| `diff` | Yes | Yes |
| `update` | Yes | No |
| `remove` | Yes | No |

`update` pulls the latest version of a component and applies a diff. `remove` cleanly removes a component and its unused dependencies.

## Code comparison

The same Button component in both ecosystems:

### shadcn/ui

```tsx
import { cva, type VariantProps } from 'class-variance-authority'
import { cn } from '@/lib/utils'
import { Slot } from '@radix-ui/react-slot'

const buttonVariants = cva(
  'inline-flex items-center justify-center rounded-md text-sm font-medium ...',
  {
    variants: {
      variant: {
        default: 'bg-primary text-primary-foreground hover:bg-primary/90',
        outline: 'border border-input bg-background hover:bg-accent',
      },
      size: {
        default: 'h-10 px-4 py-2',
        sm: 'h-9 rounded-md px-3',
      },
    },
    defaultVariants: { variant: 'default', size: 'default' },
  },
)

const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant, size, asChild, ...props }, ref) => {
    const Comp = asChild ? Slot : 'button'
    return <Comp className={cn(buttonVariants({ variant, size, className }))} ref={ref} {...props} />
  },
)
```

### gentleduck/ui

```tsx
import { cva, type VariantProps } from '@gentleduck/variants'
import { cn } from '@gentleduck/libs/cn'
import { Slot } from '@gentleduck/primitives/slot'

const buttonVariants = cva(
  'inline-flex items-center justify-center rounded-md text-sm font-medium ...',
  {
    variants: {
      variant: {
        default: 'bg-primary text-primary-foreground hover:bg-primary/90',
        outline: 'border border-input bg-background hover:bg-accent',
      },
      size: {
        default: 'h-10 px-4 py-2',
        sm: 'h-9 rounded-md px-3',
      },
    },
    defaultVariants: { variant: 'default', size: 'default' },
  },
)

const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant, size, asChild, ...props }, ref) => {
    const Comp = asChild ? Slot : 'button'
    return <Comp className={cn(buttonVariants({ variant, size, className }))} ref={ref} {...props} data-slot="button" />
  },
)
Button.displayName = 'Button'
```

The differences: `@gentleduck/variants` instead of `class-variance-authority`, `@gentleduck/primitives/slot` instead of `@radix-ui/react-slot`, `@gentleduck/libs/cn` instead of a local util, and the `data-slot` + `displayName` conventions.

## Migration from shadcn/ui

### 1. Install the gentleduck CLI

```bash
npm install -D @gentleduck/cli
```

### 2. Initialize

```bash
npx gentleduck init
```

This sets up `components.json`, Tailwind config, and CSS variables -- same structure as shadcn.

### 3. Replace components incrementally

You don't need to migrate everything at once. Both component sets can coexist. Replace one component at a time:

```bash
npx gentleduck add button
npx gentleduck add dialog
npx gentleduck add calendar
```

### 4. Remove Radix dependencies

As you replace components, their Radix dependencies become unused:

```bash
npm uninstall @radix-ui/react-dialog @radix-ui/react-popover
# etc.
```

### 5. Replace cva import

```diff
- import { cva } from 'class-variance-authority'
+ import { cva } from '@gentleduck/variants'
```

The API is the same. `@gentleduck/variants` adds memoization.

## When to use which

**Use gentleduck/ui when:**
- You want to own the full stack (primitives, calendar, keyboard, motion, state)
- Bundle size is a priority (especially for calendar: ~5 KB vs 20 KB)
- You need non-Gregorian calendar support
- You want keyboard command infrastructure (vim-style bindings, command palette)
- You want CLI commands for updating and removing components

**Use shadcn/ui when:**
- You want the largest community and ecosystem of examples, templates, and third-party integrations
- You prefer depending on Radix UI as a well-funded, externally maintained primitive layer
- You don't need calendar, keyboard, motion, or state management packages
- You need to stay on shadcn v1 for React 18 compatibility (v2 also requires React 19)
